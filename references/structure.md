# 结构：章节怎么排，摘要怎么写

章节顺序按本轮确认的结构与模板要求。如用户要求与载体的硬性条件冲突，按 [要求解析](intake.md) 裁决。没有明确结构时，再从下面的通用结构中取适用章节。

## 一、通用结构

| 章节 | 作用 | 必须回答的问题 |
|---|---|---|
| 标题 | 一眼看出做了什么 | 对象 + 方法 + 结果范围 |
| 摘要 | 独立可读的全文缩影 | 问题、方法、关键数值结果、结论 |
| 关键词 | 检索入口 | 3–6 个，不重复标题词 |
| 引言 | 建立问题与贡献 | 背景、已有工作缺口、本文做什么、贡献列表 |
| 相关工作 | 定位本文 | 前人做到哪、差在哪、本文如何不同 |
| 方法 | 可复现 | 假设、符号、模型、算法、复杂度 |
| 实验/结果 | 证明有效 | 设置、基线、指标、主结果、消融、误差 |
| 讨论 | 解释与边界 | 为什么有效、何时失效、与理论是否一致 |
| 结论 | 收束 | 回答引言提出的问题，不引入新内容 |
| 参考文献 | 可追溯 | 与正文双向对应 |
| 附录 | 细节 | 推导、代码、补充表 |

课程论文、竞赛论文可以省略"相关工作"独立成节，把它并入引言；学位论文通常需要单独的文献综述章。

## 二、摘要

**最后写。** 写在正文、结果、结论全部定稿之后。

### 四句话结构（默认）

1. **背景/问题**：一句话说明要解决什么，限定范围。
2. **方法**：1–2 句，说清用了什么模型/算法/数据，不展开公式。
3. **结果**：给出**具体数值**——提升多少、误差多少、覆盖多少，必须与正文一致。
4. **结论/意义**：一句话，说明适用条件或实际价值。

### 硬规则

- 摘要里出现的每个数字、方法名、结论，正文必须能定位。
- 不写正文没有的结论；不写"具有重要意义""填补了空白"这类无信息评价。
- 不引用文献（除非载体明确允许）。
- 不出现未定义的缩写；首次出现给全称。
- 不分段（除非官方要求结构化摘要）。
- 字数按规格表；没规定时中文 200–300 字。

### 常见错误

| 错误 | 例子 | 改法 |
|---|---|---|
| 只有背景和方法 | “本文研究了……采用了……” | 补具体结果数字 |
| 结果与正文不符 | 摘要写“提升 12%”，正文是 9.6% | 以正文表格为准重写 |
| 结论超出证据 | “证明了该方法普遍适用” | 限定为“在……条件下” |
| 堆术语 | 一句话五个缩写 | 只保留必要术语 |
| 摘要像引言 | 大段背景铺垫 | 背景压到一句 |

## 三、引言

按“漏斗”写，四段左右：

1. 领域背景与重要性（2–3 句，必须有引用支撑）。
2. 已有工作及其局限（归纳，不列流水账）。
3. 本文思路：针对上述局限提出什么。
4. 贡献列表：3 条以内，每条对应正文一个章节和一组证据。

贡献列表是审稿人最先看的部分，必须具体、可验证，不能写“提出了一种新方法”这种空话。

## 四、方法

按“变量与参数 → 假设及依据 → 数学定义 → 算法步骤 → 实现细节”展开。

- 每个符号首次出现时定义；符号表放在方法开头。
- 假设必须给依据：来自数据、文献或问题约束，不能凭空设定。
- 算法给伪代码或步骤列表，标注输入、输出、复杂度。
- 可复现性：数据来源、划分方式、超参数、随机种子写清楚。

## 五、结果

- 先给实验设置（数据、基线、指标、硬件/软件环境）。
- 主结果用表，趋势用图，二者不重复表达同一信息。
- 每个结论紧跟对应图表，正文至少引用一次。
- 报告误差：置信区间、标准差或多次运行结果。
- 对比必须公平：同数据、同划分、同评价口径。

## 六、讨论与结论

- 讨论解释“为什么”，结论回答“是什么”。
- 局限要具体：来自假设、数据、算法还是实验设计。
- 结论不引入新数据、新方法、新引用。
- 未来工作 1–2 条即可，不写清单。

## 七、按载体的差异

| 载体 | 结构要点 |
|---|---|
| 期刊论文 | 完整 IMRaD；相关工作独立；讨论充分 |
| 会议论文 | 篇幅紧；贡献前置；实验精简但要有基线 |
| 学位论文 | 加绪论/文献综述/总结与展望；章节更细 |
| 课程论文 | 按教师模板；可弱化创新，强调方法与规范 |
| 竞赛论文 | 按当届官方结构；摘要页、编号页、附录要求严格 |
