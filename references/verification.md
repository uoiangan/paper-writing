# 核验：摘要与引用必须独立查

新写、大幅改写或需要验证既有稿件时，按内容启用独立核验。局部修改将核验限于新增、改动及受影响的内容。纯排版检查源稿与成稿的文字、引注和编号对应，既有且未被改动的事实无需重查。

## 一、决定核验范围

| 本轮要核验的内容 | 检查 |
|---|---|
| 摘要 | A1 数字、A2 结论、A3 语言规范 |
| 引用 | B1 来源和元数据、B2 对正文论断的支持、B3 格式与编号 |
| 实验、仿真或计算正文 | 对关键结果回查原始数据、仪器记录或运行输出，核对量纲、统计口径和推论 |
| 两者均无且无新事实需要核验 | 摘要、引用核验不适用 |

摘要和引用由多个独立子代理复核。按实际并发分批安排检查，子代理只读，不共享彼此的先验结论。能力不可用时，可做逐项核对，但须如实记录复核方式及独立核验尚未执行的部分。主代理核对证据和分歧，抽检不少于实际引用数与 3 的较小值。

## 二、证据、版本和重跑

1. 把核验对应到交付候选版本，记录正文、文献表及相关数据的路径和版本标识，优先使用修订号或 SHA-256。核验期间冻结文件；每轮修订后复核受影响项，再确认交付版本与最新核验记录相符。
2. 给子代理文件路径、范围和明确问题。记录实际打开的证据 URL 或本地文件与页码。课程指导书、原始实验资料等可直接以原件定位，无需为本地来源寻找 DOI 或出版网页。
3. 外部来源实际检索。全文、摘要、元数据分别只能证明所访问内容覆盖的事项。主题相同或元数据匹配不能确认某个具体论断。
4. 优先按证据纠正问题，重跑受影响项。网络不可达时使用有代表性的备用来源；可用时限按条目量和任务约束确定。停止重试后标明无法核验的具体范围，按下文裁决。

## 三、受限网络下的核验路径

国内网络访问 `doi.org`、Crossref 经常超时。核验不能因为"打不开"就停，按下面顺序尝试，全部失败才判"无法核验"。

### 1. 先显式走代理

本机有代理时，把代理写进命令，不要依赖全局环境变量（子代理执行命令时环境可能不同）：

```bash
curl -sS --max-time 15 -x http://127.0.0.1:<端口> "https://api.crossref.org/works/<DOI>"
```

### 2. API 优先于网页

网页会遇到登录墙、验证码、反爬；API 一般不会。核验记录里存 API 地址即可。

| 用途 | 接口 | 说明 |
|---|---|---|
| DOI 元数据 | `https://api.crossref.org/works/<DOI>` | JSON，含作者、题名、刊名、年卷期页 |
| DOI 是否存在 | `https://doi.org/api/handles/<DOI>` | 只验证解析结果，不含元数据 |
| 题名检索 | `https://api.crossref.org/works?query.bibliographic=<题名>&rows=5` | 无 DOI 时首选 |
| 开放元数据 | `https://api.openalex.org/works?search=<题名>` | 含 DOI、被引量、开放获取链接 |
| 语义检索 | `https://api.semanticscholar.org/graph/v1/paper/search?query=<题名>&fields=title,authors,year,venue,externalIds` | 有速率限制，请求间隔 ≥1s |
| 预印本 | `https://export.arxiv.org/api/query?search_query=ti:%22<题名>%22` | 英文预印本 |
| 中文期刊 | 知网 / 万方 / 维普条目页 | 多数无 DOI，见下 |

### 3. 中文文献怎么核

- 中文期刊大量没有 DOI，"无 DOI"不等于可疑，不能据此判"无法核验"。
- 用 **题名 + 第一作者 + 刊名 + 年 + 卷期页** 五项交叉；任一项对不上，判"信息有误"并写出差异。
- 可采信的证据页面：期刊官网、知网/万方/维普条目页（须含刊名、年、卷期页）、出版社页面、学校图书馆检索结果。
- 百度学术、谷歌学术只作线索，不作最终证据；必须回到期刊或数据库条目页。
- 学位论文用学校图书馆或 CNKI 学位论文库；会议论文用会议官网或正式论文集页面。
- 用户提供的 PDF 也可以作为证据：读首页或版权页核对作者、题名、刊名、年卷期页；扫描件用 pdf skill 或 adaptive-vision-skill 读取。

### 4. 全部不可达时

- 该条判"无法核验（网络受限）"，记入本轮核验结果。
- 交付说明写明哪些检查未完成、原因和影响范围。例如：3 条文献已核对元数据，目前只读到摘要，正文对其细节的引用尚未证实。
- 网络受限的条目标记待核。按论断的重要性决定寻找替代证据、收窄表述或把稿件标为待核草稿。

## 四、Gate A：摘要核验

### A1 — 数字一致性

```text
你是论文核验员，只做检查、不改文件。
读取 <PROJECT_ROOT>/<论文文件>。提取摘要中出现的每一个数字、百分比、指标名和量化结论。
逐条在正文（含表格、图注）中定位，输出表格：
| 摘要表述 | 正文位置（节/表/图/页） | 判定（一致/不一致/缺失） | 说明 |
要求：
- 找不到对应内容的，判"缺失"，不要推测。
- 数值有出入的，写出两边的具体数值。
- 数值表必须与 <PROJECT_ROOT> 下的机器可读数据文件（CSV/JSON/脚本输出）逐格核对，不能只对照正文叙述；没有数据文件时明确写"无机器可读来源"。
- 凡出现"N/M 个""占比"等计数，必须重新计算，不得目测。
- 只报告事实。
```

### A2 — 结论一致性

```text
你是论文核验员，只做检查、不改文件。
读取 <PROJECT_ROOT>/<论文文件>。
逐条核对摘要声称的：研究方法、主要贡献、最终结论。
判断正文是否有对应章节、数据或论证支撑，以及摘要是否夸大。
输出表格：
| 摘要声称 | 正文依据（位置） | 判定（支持/部分支持/无支撑/夸大） | 说明 |
特别检查：摘要是否出现正文没有的新结论、新方法、新数据。
```

### A3 — 语言与规范

```text
你是论文核验员，只做检查、不改文件。
读取 <PROJECT_ROOT>/<论文文件> 的摘要部分，核对：
1. 字数是否符合要求（给出实际字数）；
2. 关键词数量、是否重复标题词；
3. 缩写是否在首次出现时给出全称；
4. 是否出现未在正文定义的新术语；
5. 是否使用了"具有重要意义"等无信息评价；
6. 中英文摘要是否语义一致（若两者都有）。
7. 过度表述：显著（无统计检验不得用）、最广/最优/首次/完全/经典/常用（文献未明说则改）；"同步上升/单调增长"等断言是否与数据逐点一致。
输出逐项结论表，并给出修改建议。
```

## 五、Gate B：引用核验

### 分片规则

- B1 按条目数量和检索难度拆分；B2 可按章节拆分。B3 优先用结构化工具核对编号和双向对应，并独立复看。

### B1 — 存在性（最重要）

```text
你是文献核验员。只核验，不改文件。
读取 <PROJECT_ROOT>/<参考文献文件或论文的参考文献部分>。
对每一条文献：
1. 有 DOI：打开 https://doi.org/<DOI>，核对作者、题名、年份、期刊/会议、卷期页。
2. 无 DOI 的外部来源：按第三节选择与类型对应的出版社、主办方、期刊或数据库。
3. 本地资料：打开原件核对名称、版本和具体位置。记录实际打开的证据 URL 或本地文件与页码。
输出表格：
| 编号 | 条目原文 | DOI/证据URL | 判定（真实/信息有误/查无此文/无法核验） | 具体错误 |
规则：
- 不得凭记忆判断文献是否存在。
- 作者顺序、年份、卷期页、题名任何一项不符，判"信息有误"并写出差异。
- 检索不到，判"查无此文"或"无法核验"，不得判"真实"。
- 按任务时限尝试实际可用的证据路径；用尽合理路径后记录无法核验的条目、已尝试途径和原因。
```

### B2 — 相关性

```text
你是引用相关性核验员。只核验，不改文件。
读取 <PROJECT_ROOT>/<论文文件>。
找出正文中每一处引用（数字编号或作者-年份），连同它所在的那句话一起摘出。
对每条引用，读该文献的摘要（必要时读原文可得部分），判断它是否支持这句话的主张。
输出表格：
| 正文位置与主张 | 引用编号 | 原文页/段/图与证据链接或本地路径 | 判定（直接支持/部分支持/仅背景/不支持/无法判断） | 说明 |
特别标出：引用与句子主题无关、引用结论被反向使用、一句话引用过多文献但只有一篇相关。
```

### B3 — 格式与完整性

```text
你是参考文献格式核验员。只核验，不改文件。
读取 <PROJECT_ROOT>/<论文文件>。
核对：
1. 正文引用编号与文末条目双向对应：每个 \cite/上标都有条目，每个条目都被引用；
2. 顺序编码制编号连续且同一条目复用同一编号；作者—年份等体例按其规则核对；
3. 同一文献不重复出现（按 DOI 或题名判断）；
4. 条目风格统一（GB/T 7714 / APA / IEEE / Vancouver，按规格表）；
5. 按来源类型与引用体例核对必需字段；本地教材、原始记录等使用其实际版本和定位信息；
6. 中英文文献的标点、大小写是否符合所选风格。
输出：问题清单（编号 + 问题类型 + 修正建议）。
```

## 六、汇总与裁决

将适用的核验结果并入项目工作记录；条目多、需要独立审计或用户要求时可单列。保留以下信息：

- 交付候选的文件、修订号或 SHA-256，以及本次检查范围和方式。复用的历史核验注明对应版本和未受影响的范围。
- 每条来源的证据位置和访问范围；对关键、变动和有争议的主张，记录正文定位、对应证据位置、支持程度和修改后状态。本地来源记录原件和具体页码、图表或数据行。
- 从源稿、渲染结果、编译辅助文件或 DOCX 结构按体例统计引注位置和参考条目，注明范围。编号制检查首次出现顺序、重复使用和正文/文末匹配。数据型结论记录重算口径。
- 记录发现、实际修复、受影响项复核结果、主代理抽检及仍待确认的事项。使用「通过、待核、不通过、不适用」等真实状态。

发现错误或不支持时，按证据修正、换引、收窄或删去相关论断，复核修改后的版本。证据只支持背景时，正文也只能把它用于背景。关键结论、必需数据或硬性要求尚未通过时，可按用户用途提供明确标为待核的草稿；已核验终稿须先解决这些问题。其余限制是否影响交付依载体和用户要求判断，并在交付说明具体注明。
